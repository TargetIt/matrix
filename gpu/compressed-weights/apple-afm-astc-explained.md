# Apple AFM 论文深读：为什么语言模型的权重能用 ASTC 纹理压缩？

一句话：**Apple 没有把模型变成图片，也没有无损地保存所有权重；它把权重当作数值数组，用纹理格式近似保存，再借用 GPU 的解码硬件，并训练小型适配器弥补误差。**

本文专读 Apple 的 [《Apple Intelligence Foundation Language Models: Tech Report 2025》][paper]，重点是 [§6，PDF 第 13–14 页][optimization]和 [Table 3，第 17 页][evaluation]。初版发布于 2025-07-17；本次核查日为 **2026-09-10**，采用最新修订 **v3（2025-08-27）**，并逐项对比了此前引用的 v1：这里涉及的压缩段落和 Table 3 数字没有变化。

范围提醒：这是 **2025 年模型**的技术解读。Apple 已发布 [2026 年第三代模型介绍][afm3]，不能把本篇 ASTC 方案自动当成所有新模型的实现。文中“论文披露”是事实；公式、玩具数字和系统分析是本文解释，不是 Apple 未公开的实验结果。

## 1. 压的究竟是什么？

### 1.1 不是用户图片，是训练好的参数

先把神经网络看成一串计算。最基本的一步是：

$$y = Wx$$

`x` 是这次输入产生的特征；`W` 是训练学到的一张数字表，也就是权重矩阵；`y` 是下一步要用的特征。例如一行权重 `[0.2, -0.7, 0.3]` 表示把三个输入分别乘这些数，再相加。

语言模型里的注意力投影、前馈网络、专家网络都大量使用这种计算。权重不是文字的 ZIP 包，也不是“一颗权重对应一个知识点”；它们共同决定如何处理输入。训练好以后，基础权重通常不随每次提问变化，所以可以提前花时间压缩，反复使用。

论文的服务器模型是 PT-MoE Transformer：多条计算轨道配合专家网络。**MoE 决定当前输入使用哪些专家；ASTC 决定权重如何保存。** 前者减少部分计算，后者减少每份权重的存储和搬运，不是同一种“稀疏”。[架构原文 §2.2][architecture]

### 1.2 同一篇论文，其实用了几条不同路线

| 数据对象 | 2025 端侧模型（约 3B） | 2025 PCC 服务器模型 |
| --- | --- | --- |
| 语言解码器主体权重 | 2 bit/weight，量化感知训练 QAT | ASTC，正文口径约 3.56 bit/weight |
| 词嵌入表：把 token ID 映射成向量 | 4 bit，参与 QAT | 4 bit，训练后量化 |
| KV cache：本次上下文的注意力历史数据 | 8 bit | 8 bit |
| 质量恢复 | 训练低秩适配器 | 分离主要奇异成分，再压缩、训练低秩适配器 |

来源：[论文 §6][optimization]及 [Apple 官方说明的压缩表][updates]。论文没有给出足以复现的逐张量白名单，也没有逐一说明视觉编码器、路由器等全部模块的位宽。

所以，“Apple 用 ASTC 压权重”在这里成立；“iPhone 的 2 bit 模型就是 ASTC”“所有张量都用 ASTC”“ANE 用纹理单元解码”都不是这篇论文的结论。

## 2. 第一性原理：为什么权重允许被近似？

### 2.1 保存数值的精确性，不等于完成任务所需的精确性

假设某个权重是 `0.12347`，压缩还原后变成 `0.125`。数字已经改变，但乘上某个输入后造成的误差，可能不足以改变下一词的选择。

这里有三个不同的目标：

1. **逐位相同**：还原后的二进制完全一致。这是无损压缩的目标。
2. **数值接近**：还原值接近，但不完全相等。这是有损数值压缩的目标。
3. **任务表现接近**：模型分数、回答质量或输出决策接近。这才是模型部署最终关心的目标。

第二项不自动保证第三项，第三项更不要求第一项。Apple 的路线是接受第二项的误差，再通过训练尽量守住第三项。

FP16 本身是有限精度浮点格式，16 位中包含符号、指数和有效数字信息。即使解码结果仍用 FP16 装着，也不代表原来每个 FP16 数都被精确保留：**容器能装多精细，与压缩数据实际保留多精细，是两件事。**

### 2.2 任意数据不可能都无损缩成四分之一

36 个 16 位值占 `36 × 16 = 576 bit`。如果只剩 144 bit，包括下文的块偏移，能区分的编码组合大幅减少；不可能给所有原始组合都分配不同编码。不同输入必然可能压成同一个结果，解码器无法知道原来究竟是哪一个。

无损方法只有在数据确实存在可利用的重复、偏斜等结构时才能缩小，不能保证任意输入都缩小。ASTC 的固定块大小能够稳定给出存储预算，代价正是允许失真。

因此这里最重要的问题不是“这些浮点数有什么魔法能无损变小”，而是：**在哪些方向上，少保存一点信息仍然够用？**

### 2.3 神经网络有什么可以利用的余地？

通常有三类余地，但要分别验证，不能一句“神经网络有冗余”就结束：

- **数值精度余地**：一些小数细节对当前任务不敏感。
- **矩阵结构余地**：一张大矩阵的主要变化可能集中在少量方向上，可以把这些方向单独保存。
- **再训练余地**：参数改变后，仍可通过调整其他参数，让整体功能接近原来。

Apple 在 §6 明确利用了后两项：分离主要奇异成分、训练恢复适配器。它没有证明所有模型都具有同样压缩空间。

## 3. ASTC 究竟怎样把数变少？

### 3.1 “纹理”在硬件看来也是数字数组

ASTC 是 Arm 与 AMD 开发的块式纹理格式，原始论文发表于 [HPG 2012][astc-paper]。图像中的像素颜色是数，网络中的权重也是数；解码硬件负责按格式重建数值，不会判断它是草地颜色还是神经网络参数。

但把矩阵排列成二维数组，**不会自动让相邻权重像自然图片一样平滑**。是否适合某种块模式、排列顺序是否影响误差，都需要测量。AFM 论文没有披露完整的权重重排和通道映射算法。

### 3.2 128 bit 存的是“一小块数据的描述”，不是 36 个独立小浮点数

ASTC 把纹理切块，每个压缩块固定 128 bit。一个直观但简化的理解是：

> 不逐个写下所有数，而是记录范围的两端，以及每个位置靠近哪一端。

在最简单的标量线性插值示意中：

$$\hat v_i = (1-t_i)a + t_i b$$

`a、b` 是共享端点；`t_i` 表示第 i 个位置在两端之间哪里。比如端点为 `0、1`，只允许 `t=0、1/3、2/3、1`，那么 `0.32` 可以用“第二档”表示，重建为约 `0.333`。

这是解释“共享描述”的玩具例子，**不是 AFM 实际码字，也不是 HDR 的精确解码公式**。真正 ASTC 还可以选择分区、多组端点、端点精度、插值系数精度，以及较稀疏的系数网格。模式信息也占用这 128 bit，不能把整块位数都算成每个位置独占的精度。[Arm 格式说明][astc-format]

特别注意两个同名概念：ASTC 文档的 *texel weights* 是**插值系数**，不是语言模型的网络权重。前者用来重建后者。

### 3.3 再深入一层：哪些地方丢信息，哪些地方不丢？

端点与插值系数要量化，复杂块只能用有限模式近似；如果采用低分辨率系数网格，还会引入空间表达限制。这些是失真来源。

ASTC 还用 BISE（有界整数序列编码）紧凑保存已经选好的离散符号。例如三个五选一的符号共有 `5³=125` 种组合，7 bit 足够；逐个用 3 bit 则需 9 bit。**这一步打包可以不损失离散符号，但之前把原始数值变成符号已经可能有损。** 不能因其中有无损步骤，就把整体叫无损。[ASTC 原始论文 §3.2][astc-paper]

HDR 又有一层容易误解的细节：实际解码在编码域插值，再转为浮点；不是简单地在原始实数端点间做均匀插值。Arm 解码源码的 `lerp_color_int()`、`decode_texel()` 展示了整数插值、HDR 的 LNS 转换与 FP16 重建。因此，不能把 ASTC-HDR 当成一个普通的“均匀 INT4 量化器”。[解码源码][astc-decode]

### 3.4 为什么 AFM 选 HDR？3.56 bit 又怎么来？

论文使用的 HDR-ch 路线能表示非负的浮点通道数据；相比把数硬塞进普通 `[0,1]` 的低动态范围颜色表示，它更适合这里的数值范围。HDR 也不等于无限范围、无限精度。

论文明确说：**每块 6×6，对应 36 个网络权重，编码成 128 bit。** 所以：

$$128/36 \approx 3.56\ \text{bit/weight}$$

这是平均码率，不存在一个独立的“3.56 位浮点类型”。也不能因为 ASTC 支持多通道，就擅自把论文的 36 个权重改算成 108 或 144 个。

名称旁证：Arm 命令行的 `-ch` 对应 RGB HDR、alpha LDR，`-cH` 才是全部通道 HDR。[选项定义][astc-cli]与 [编码说明][astc-encoding]可以核实这个区别；但这不能证明 Apple 使用了该命令行工具，或揭示其实际 RGBA 映射。

## 4. Apple 如何把它接进语言模型？

完整逻辑不是“整个矩阵直接交给 ASTC”，而是下面这条链。以下只表达数据依赖，不代表 Apple 未公布的芯片缓存布局。

```text
训练好的权重矩阵 W
       │
       ├─ 主要奇异成分 → 小型低秩分支 BA ───────────────────┐
       │                                                  │
       └─ 剩余矩阵 R → 6×6 分块 → 每块减最小值 m           │
                                  │                       │
                         ASTC 编码 + 单独保存 m            │
                                  │                       │
                         GPU 硬件解码、加回 m              │
                                  │                       │
                              重建 R̂                     │
                                  └──── R̂x + B(Ax) ──────┘
                                             │
                           冻结压缩基座，训练适配器恢复质量
```

推理时只执行已经训练好的两条分支；图末“训练”是部署前的恢复阶段，不是每次回答都训练。

### 4.1 先把“主要方向”单独拿出来

矩阵可以写成：

$$W = U\Sigma V^T = BA + R$$

理解 SVD 不必先学矩阵分解算法：把它想成找出这张数字表最强的几种变化模式。`BA` 保存前 r 个主要模式，`R` 保存剩下的部分。不是把几个最大的单独数值挑走；**一个模式通常同时影响许多行、许多列。**

对一个 m×n 矩阵，低秩分支的两张小表只需 `r(m+n)` 个数，而完整矩阵有 `mn` 个。以本文假设的 4096×4096、r=16 为例，前者参数量约为后者的 0.78%；这不是 Apple 披露的层尺寸或秩。

Apple 把主要成分放进适配器，仅对剩余基座应用 ASTC。[§6 Quality Recovery Adapters][optimization]引用的是 Meng 等的 [PiSSA（NeurIPS 2024）][pissa-paper]，不是一句没有来源的“保留重要权重”。

这里有两个边界：主要成分**绕开的是 ASTC 压缩**，论文没有披露它们统一采用什么位宽；SVD 按矩阵自身的能量选方向，也不等于精确找出了每个真实任务最重要的方向。

### 4.2 为什么这样通常更容易压？

一个极简例子：

```text
W = [10.01  9.99]    BA = [10  10]    R = [ 0.01 -0.01]
    [ 9.99 10.01]         [10  10]        [-0.01  0.01]
```

大体上“每个位置都接近 10”的主模式先被单独保存，压缩器只处理余下的小变化。在这个例子里，剩余数值的幅度明显减小。

但不能泛化成“拿掉主成分，剩下必然平滑或全是噪声”。实际残差仍可能有不规则结构、异常值和重要信号；固定块编码的误差还取决于其模式。低秩分离创造了更有利的条件，不是数学上的零误差保证。

### 4.3 负权重怎么办？每块平移，再把偏移存下来

对 ASTC 要处理的一块残差，记最小值为 `m`，先做：

$$z_i=R_i-m\geq 0$$

以四个数示意：

```text
原值 R：      [-0.30, -0.10,  0.20, 0.50]
最小值 m：    -0.30
平移后 z：    [ 0.00,  0.20,  0.50, 0.80]
假设解码 ẑ： [ 0.00,  0.21,  0.49, 0.80]
加回 m：      [-0.30, -0.09,  0.19, 0.50]
```

这组“假设解码值”只用于解释，不是实际运行 ASTC 的结果。可以直接看出：加回最小值恢复了正负号所在的数值范围，**没有消除中间编码造成的 ±0.01 误差**。

在精确算术中，减 m 再加 m 是可逆的。论文所说的 min-shift 无损，限定的就是这个变换；不能扩大成整个 ASTC 无损。实际浮点运算还要考虑舍入、溢出等边界，不能额外推断逐位可逆。

平移也不会压缩块内极差：`max(R−m)−min(R−m)=max(R)−min(R)`。它解决的是**负数不符合格式**，不是解决异常值和动态范围的一切问题。

### 4.4 偏移不是免费元数据：完整块约 4 bit/weight

每块最小值单独用 FP16 保存，所以仅按论文描述做存储复算：

| 项目 | 每 36 个权重的空间 |
| --- | ---: |
| 16 位基线 | 72 字节 |
| ASTC 载荷 | 16 字节 |
| FP16 最小值 | 2 字节 |
| 载荷加最小值 | 18 字节，即 4 bit/weight |

`72/18=4`，也就是这个局部口径约四倍压缩；单看载荷才是 `16/3.56≈4.5` 倍。适配器、其他位宽的张量、对齐、容器和运行时副本还没计入，**不能宣称整个模型一定缩小四倍**。

### 4.5 最后训练补偿分支，不是“把丢失的比特找回来”

设解码后的残差为 `R̂=R+E`，恢复训练前的层计算是：

$$\hat y=\hat R x+B(Ax)=Wx+Ex$$

训练时压缩基座固定，调整低秩适配器，使模型在训练数据上的任务损失降低。它不是读取原始数值的神奇解压器，而是学会在“底座已经发生偏差”的条件下继续工作。

小型适配器不能保证精确表示任意全秩误差；它可以在任务常见的输入方向上做有效补偿。恢复好不好，取决于秩、数据覆盖、误差结构和训练，必须最终评估。

## 5. 同样的误差，为什么有时没事、有时出事？

### 5.1 核心是 Ex，不是只看 E

一行权重的误差为 `e=[0.01,-0.01]`：

| 输入 x | 输出误差 e·x | 含义 |
| --- | ---: | --- |
| `[1,1]` | 0 | 这个输入上刚好抵消 |
| `[1,-1]` | 0.02 | 相同误差变成相加 |
| `[100,0]` | 1 | 大激活把小权重误差放大 |

所以“小数点只变一点”不是充分理由；“许多误差平均会抵消”也只有在额外统计条件下才可能成立。

对于输入分布，更完整的层输出均方误差是：

$$\mathbb{E}\|Ex\|_2^2=\operatorname{tr}(E C_x E^T),\qquad C_x=\mathbb{E}[xx^T]$$

这里 `C_x` 是输入的二阶矩，不要求均值为零。白话就是：**误差是否刚好落在输入经常使用、幅度很大的方向，比只看权重重建平均误差更重要。** [AWQ 原始研究][awq]也是从激活统计而非仅从权重大小识别敏感通道；这只是辅助理解，不能据此声称 Apple 用了 AWQ。

### 5.2 数值改变，也可能仍然选中同一个答案

假设两个候选词的分数是 `10、8`，分别变化不到 `0.1`，第一名不会变。若分数是 `10、9.99`，很小的扰动就可能换第一名。

更一般地，若每个候选分数的误差绝对值都不超过 ε，原第一名比第二名高出超过 `2ε`，那么贪心选择的第一名仍能保持。这是一个简单的充分条件，不代表整段生成都有这样的误差界。

如果用随机采样，概率变了就可能抽到不同词；如果前面的词变了，后面的输入上下文也变了。**最终文字不完全一致，不必然表示质量下降；平均质量相近，也不表示每个问题都不受影响。**

### 5.3 为什么某些部位特别敏感？

大输入激活会放大权重误差；多层计算可能放大或抑制已有误差；注意力分数、归一化和专家选择还会改变信息流。特别是 top-k 路由接近选择边界时，小变化可能换掉一个专家。

这说明应检查真实任务中的分布和决策边界，而不是凭“全是浮点矩阵”统一选格式。以上是机制分析，论文没有给出每类模块的敏感度排名。

## 6. 为什么不能把网络里所有东西都这样压？

准确说，不是分成“数学上能压”和“绝对不能压”两类，而是同时考虑 **能否近似、误差是否可接受、硬件代价是否值得**。

| 数据或情况 | 为什么要区别对待 | 本论文能确认什么 |
| --- | --- | --- |
| 解码器静态大矩阵 | 可提前编码，反复读取，节省带宽的价值高 | 服务器主体采用 ASTC |
| 主要奇异成分 | 影响较强，单独用低秩形式保存比较经济 | 适配层的这些成分不经 ASTC |
| 词嵌入表 | 查表访问与矩阵计算不同，精度/收益要单独评估 | 使用 4 bit；没有给出“为何不选 ASTC”的单项消融 |
| KV cache | 随输入和序列增长；编码发生在运行时，数据分布也不同 | 使用 8 bit，而不是文中 ASTC 权重方案 |
| 其他动态激活 | 刚算出来就要消费，复杂在线编码可能得不偿失 | 没有完整的逐激活位宽清单 |
| 归一化统计、累加中间值 | 小误差可能影响整组数据；累加还涉及溢出和误差积累 | 不能从权重位宽反推它们的位宽 |
| token ID、地址、张量尺寸、控制索引 | 通常要求语义上精确，改一个值可能选错对象 | 不是 ASTC 近似数值压缩的目标 |
| 极端离群值、难以拟合的块 | 有限码率不足以兼顾大范围和局部细节 | 论文未公开残差分块统计或逐块回退策略 |

注意：KV cache 并非“不能压”，Apple 就量化到了 8 bit；离散索引也可以无损编码，但不能随意有损近似。不同对象适合的是不同压缩合同。

用普通均匀量化作直觉示意：范围为 `[0,1]`、16 档时，间隔约 `1/15`；若一个异常值把范围撑到 `[0,100]`，间隔变成约 `100/15`，许多小值就难以区分。ASTC-HDR 的实际档位不是这样均匀分布，但有限预算下的范围—细节矛盾仍然存在。

手机端 2 bit QAT 的意义也在这里：不是训完直接砍位数，而是在训练中模拟量化，让模型适应少数可用档位。论文还学习裁剪范围以减轻离群值影响。**QAT 是训练方法；ASTC 是编码格式。** 两者属于不同层次，理论上可以组合，但不能把未披露的组合写成 Apple 的实际做法。

## 7. 为什么复用纹理硬件值得做？

### 7.1 关键不是文件下载小，而是推理时少搬数据

如果模型只在磁盘上压缩，启动后全部展开成 16 位权重，运行时仍要搬运大数组。Apple 则利用 GPU 固定功能硬件边取边解码，让压缩存储服务于实际计算。[论文第 14 页][optimization]

自回归解码每次生成一个 token，常见低批量场景下，每读取一份权重做的计算不多，容易受带宽限制。假设当前一步所用 N 个权重各从内存读取一次，16 位权重流量约 `2N` 字节；按 4 bit 的块加偏移口径则约 `0.5N` 字节。这个例子忽略缓存复用、适配器和其他数据，解释的是上限方向，不是 Apple 实测 token/s。

prefill 同时处理多个输入 token，一份权重可被更多计算复用；批量变大、上下文变长时，算力、KV 访问等也可能成为主要瓶颈。因此，少四倍权重字节不等于快四倍。

### 7.2 为什么不用 ZIP 这样的通用压缩？

ASTC 固定长度、独立分块，可由位置计算块地址，并只解需要的块。图形硬件早就需要随机访问纹理，恰好提供了这种能力。[ASTC 格式说明的 Block compression][astc-format]

相比之下，通用压缩流往往要处理更多依赖、索引或周边数据，除非额外做分块设计。即使比 ASTC 压得更小，没有合适的解码通路也未必推理更快。

这里的取舍是：**牺牲一部分表示精度，换取确定的块预算和已有的高速解码器。** 不是 ASTC 天生比所有神经网络专用格式更准确。

### 7.3 “零 compute cost”应该怎么读？

论文的限定是从 shader/compute core 的角度看，固定功能单元承担解码；加回最小值融合进张量运算，不另做整张矩阵重建。作者还报告 prompt 阶段没有引入额外延迟。

这不能翻译成“零电耗、零芯片面积、无限吞吐”。解码单元、访问偏移、适配器计算都有物理代价；吞吐能否匹配矩阵计算、是否与其他工作争资源，都需具体平台测量。论文没有公开缓存各级的压缩状态和硬件队列细节。

实现时也必须使用正确的 HDR 格式和访问方式：不能误用 sRGB 转换或把相邻权重当图像做过滤。Apple 的 [Metal `astc_6x6_hdr` 格式][metal-format]是真实 API，但格式存在不等于公开了 AFM 内核；HDR 支持还应按 [GPU family 功能表][metal-table]检查。

## 8. 论文证明了什么，还没证明什么？

### 8.1 “压完完全不影响效果”不成立

直接看 [Table 3][evaluation]，这里采用同一张表的前后对照，不混入官网博客的另一组分数：

| 模型 | MMLU 优化前 → 后 | 变化（百分点） | IFEval 优化前 → 后 | 变化（百分点） |
| --- | --- | ---: | --- | ---: |
| 端侧 | 67.8 → 64.4 | −3.4 | 85.1 → 82.3 | −2.8 |
| 服务器 | 80.0 → 79.2 | −0.8 | 89.1 → 90.2 | +1.1 |

MMLU 主要衡量多领域知识问答，IFEval 检查可验证的指令遵循。表格说明一些能力有下降，另一些指标可以持平或改善。

但它比较的是**完整优化组合**，不是只开关 ASTC 的控制实验。不能把下降都算到 ASTC 头上，也不能把提升当成 ASTC 本身提高了模型能力。单项改善可能与恢复训练等有关，论文没有提供足以分离原因的消融和统计置信信息。

### 8.2 仍缺少哪些材料？

本次检索论文、[Apple 官方研究入口](https://machinelearning.apple.com/research/apple-foundation-models-tech-report-2025)、[Apple 的公开模型列表](https://huggingface.co/apple/models)以及相关源码，没有找到可对应复现该服务器方案的完整权重包和 ASTC 推理内核。**“未找到”不等于断言任何地方都不存在。** 当前可核查材料仍不足以回答：

- 全部目标层、每层适配器秩、适配器实际位宽和元数据布局。
- 权重到纹理的完整映射、编码器参数、是否采用任务感知误差度量。
- ASTC 单独造成的质量损失，以及每个恢复步骤分别挽回多少。
- 不同块尺寸的质量—速度—内存对照，及为何最终选 6×6。
- 同硬件同任务下，和 INT4、码表量化等方案的严格对照。
- 具体缓存位置、解码吞吐、整模型占用和可隔离的功耗收益。

所以最稳妥的结论是：**Apple 展示了一条实际采用的软硬件协同路线，而不是公布了一个对任意模型都无损、免费、最优的压缩算法。**

## 10. 追加分析：只有 INT8 的 Matrix Core，能否使用 ASTC？

**可以把 ASTC 当成 INT8 权重的存储格式，但不能直接当成 Matrix Core 的计算格式。** 是否值得做，取决于解码后能否低成本供给 INT8 计算，以及模型能否承受新的误差。INT8 已经小，并不意味着没有压缩空间；也不意味着再压一次仍然安全。

本节以“Matrix Core 的矩阵操作数仅支持 INT8”为给定条件；不假设整颗 GPU 只有整数运算，也不假设它已经有 ASTC 解码器、直连通路或特定累加位宽。以下设计是针对这一约束的方案分析，**不是 Apple 已公布的 INT8 产品实现**。核查日期：2026-09-10。

### 10.1 先分开三个格式：存储、解码输出、计算输入

```text
内存中的 ASTC 块
      ↓ 固定功能 ASTC 解码器（如果芯片已有且可供计算使用）
归一化数值 / 浮点结果 / 可访问的 UNORM8 中间值
      ↓ 舍入、符号恢复、打包、矩阵 tile 重排
片上 INT8 权重 tile
      ↓
INT8 Matrix Core × INT8 激活 → 累加 → 输出重定标
```

Matrix Core 只需看到合法的 INT8 操作数，它不必理解 ASTC。反过来，**支持 INT8 乘法不等于具备 ASTC 解码能力**；若没有现成解码器，用通用计算核模拟复杂 ASTC 解码，成本可能吃掉带宽收益。

ASTC 的默认解码精度通常是 FP16；Khronos 还定义了 LDR 的 UNORM8 解码模式。UNORM8 表示归一化到 `[0,1]` 的无符号数，**不是有符号 INT8 矩阵操作数**，也不意味着 API 会把原始 8 位整数直接交给 Matrix Core。[Khronos 解码精度说明][int8-decode-spec]

若我们能修改硬件，LDR 内部的整数处理有机会接到“取 8 位 → 转有符号 → 打包”通路；若只能使用已有 API，就必须按该 API 返回的数值类型转换。标准中的解码模式不是对我们芯片或 Apple Metal 的自动支持承诺。

### 10.2 对已经量化的 INT8，先试 LDR，不必照搬 HDR

常见量化关系是：

$$w\approx s_w(q_w-z_w)$$

`q_w` 是保存的 INT8，`s_w` 是尺度，`z_w` 是零点。例如 LiteRT 的常见卷积权重使用逐输出通道尺度、对称整数范围 `[-127,127]` 和零点 0；这只是公开范例，实际应服从我们的模型格式。[INT8 量化规范][int8-quant-spec]

一种简单的候选映射是把有符号整数平移成无符号整数：

$$u=q_w+128,\qquad v=u/255$$

对完整 `[-128,127]` 范围，`u` 正好落在 `[0,255]`。将 v 作为 **线性、非 sRGB** 的单通道 ASTC-LDR 数据编码；解码得到 v̂ 后：

$$\hat q_w=\operatorname{clip}_{[-128,127]}\bigl(\operatorname{round}(255\hat v)-128\bigr)$$

如果模型禁止 −128，就进一步按其合法范围裁剪。若可直接取得 UNORM8 的整数码 û，则执行 `q̂=û−128`；不要把无符号字节原样强制解释成有符号字节。中间转换应使用足够宽的类型，避免溢出。

这个固定偏移不需要每块存 FP16 最小值；原来的量化 scale/zero-point 仍保留。**平移只改变压缩接口，不应擅自改变模型零点。** 解码和转换可以使用浮点或整数逻辑，只要最终产生一致的 INT8；Matrix Core 本身无需因此新增 FP16 矩阵乘法。

单通道输入可采用 Arm 建议的 `rrr1` 编码映射，重复的 RGB 只是同一个标量，不是三个网络权重。硬件采样应禁用会混合不同位置的线性过滤、mipmap 等行为，并避免 sRGB 转换。[Arm 单通道映射与解码规则][astc-encoding]

这是便于建立基线的方案，**不是已证明质量最优的方案**。整数直方图、相邻位置的可拟合程度、编码器的误差目标都会影响结果。若采用逐块范围缩放，则需增加范围元数据和还原运算，重新算收益；若直接压浮点权重再量化到 INT8，则是另一条误差链，不能与“压现有 INT8”混算。

### 10.3 INT8 已经只有 1 字节，空间上还值得吗？

下面统一假设：**一个纹理位置对应一个 INT8 权重，块完整填满**。LDR 固定偏移方案没有新增逐块偏移；表中不计双方共有的量化尺度、容器、对齐与回退索引。

| 存储方案 | 平均 bit/weight | 相对原 INT8 的压缩倍数 | 节省权重字节 |
| --- | ---: | ---: | ---: |
| 原始 INT8 | 8 | 1× | 0% |
| ASTC-LDR 4×4 | 8 | 1× | 0% |
| ASTC-LDR 5×5 | 5.12 | 1.56× | 36% |
| ASTC-LDR 6×6 | 3.56 | 2.25× | 55.6% |
| ASTC-LDR 8×8 | 2 | 4× | 75% |
| 照搬 AFM 的 6×6 载荷 + 每块 FP16 偏移 | 4 | 2× | 50% |

复算规则是 `128/块内权重数`，压缩倍数为 `8/平均位数`。最后一行仅算存储；HDR 到 INT8 的转换、残差分支等成本还没加入。

**因此有空间可省，但从 INT8 出发，不能沿用 FP16 基线的“四倍左右收益”。** 4×4 单标量方案连载荷都不省，却仍可能有损；5×5、6×6 才有较明确的存储动机。8×8 的码率更低，但绝不能仅凭表格认为精度可接受。[ASTC 块尺寸表][astc-format]

把更多独立权重塞入 RGBA，可改变每权重码率，但不能把收益简单再乘四：多个独立通道共享有限编码预算，ASTC 的通道相关性假设和模式限制可能显著影响精度，解码输出和重排也要计费。它应是单独实验，不是本表的免费优化。

### 10.4 再有损一次，误差会不会太大？

**有风险，但不能仅凭 INT8 这个名字判断可接受或不可接受。** INT8 表示可用的整数网格，不代表这张矩阵的全部 8 位都不可舍弃；也不代表剩余精度仍然充裕。

若把已有 INT8 又有损压缩，最终实数权重误差可以分成：

$$\hat w-w_{\rm original}=
\underbrace{s_w(q_w-z_w)-w_{\rm original}}_{\text{原 INT8 量化误差}}
+\underbrace{s_w(\hat q_w-q_w)}_{\text{ASTC 及还原新增误差}}$$

这里假设尺度和零点不变。两项不保证独立，也不保证抵消，不能简单相加两个“平均精度损失百分比”。

有一个很实用的判断：在上述映射和最近舍入下，若每个位置的完整解码误差都满足：

$$|255\hat v-u|<0.5$$

还原后的整数就仍是原来的 q。也就是说，**有损纹理解码有时可能在最终 INT8 网格上恰好不变**。但 ASTC 不保证任意块都满足这个条件；想声称无新增数值损失，必须逐元素验证 q̂=q，并保持后续运算语义一致。

一旦整数变了，误差大小需要乘回尺度看。假设某通道 `s_w=0.02`，整数误差 +3 对应实数权重误差 +0.06；它乘输入 0.5 时贡献 +0.03，乘输入 100 时贡献 +6。它若发生在接近零的权重上，相对误差可能很大，但最终仍要看它参与了什么计算。这些是算术示例，不是 ASTC 实测误差。

对一个输出通道、尺度固定的点积，新增误差为：

$$\Delta y=s_w s_x\sum_j(\hat q_{w,j}-q_{w,j})(q_{x,j}-z_x)$$

这说明测 `q̂−q` 的均方误差还不够，还应测真实激活下的层输出误差、关键任务和异常输入。编码时若混合不同量化尺度的通道，用普通纹理误差目标可能把不同实数影响错误地当成同等重要。[激活敏感性的研究背景：AWQ][awq]

不要只看权重图片 PSNR。对神经超分/插帧，既要检查整帧画质，也要检查细线、文字、运动边界和连续帧闪烁；对分类、检测或语言任务，则用各自的任务指标。没有我们的权重、验证集和质量预算，**当前不能给出“最多下降 1%”之类保证**。

### 10.5 Apple 的质量恢复方案不能原样移到 INT8-only Core

Apple 保留主要奇异成分并训练适配器，但论文没有说明这条分支是怎样在一个“所有矩阵操作数都只能 INT8”的引擎上执行的。若我们也保留 `B(Ax)`，就必须回答：A、B 是否也量化到 INT8？中间 Ax 用什么尺度？两条输出怎样对齐尺度再相加？累加、饱和和重定标在哪里完成？

这些可能用额外 INT8 运算和足够宽的累加实现，也可能需要其他计算单元；**不能默认拥有一条免费的高精度补偿旁路**。若把补偿分支合并回 W 后又重新 ASTC 编码，原先“主成分绕开 ASTC”的保护也就不再自动成立。

若可重新训练，应让恢复训练看到最终部署链中的 ASTC 重建、INT8 舍入/裁剪和激活量化误差，而不仅是普通 INT8 QAT。ASTC 块模式搜索不可直接按普通连续运算求导，实际需要模拟、近似梯度或阶段性重新编码等设计；这属于后续研发，不是现成开关。

如果只能使用现有 INT8 模型、没有恢复训练数据，则更适合保守地评估较高码率、按层回退或无损方法，不能援引 Apple 的服务器评测替我们担保质量。

| 能将来自 INT8 的数映射成 LDR 纹理，解码后再转换成整数吗？ | 格式上可构造，属于应用/内核实现；不是 ASTC 原生 SINT8 格式，也不是直接把 ASTC 码字送入整数乘法器。 |
| AFM 论文是否证明 Apple 已部署“ASTC → INT8 Matrix Core”的神经网络通路？ | 没有。论文披露的是 HDR 权重压缩与质量恢复，没有给出这个 INT8-only 通路，也没有给出其质量/性能数据。 |
| Apple 未来会不会提供自动支持或专用接口？ | 当前公开材料不足以判断，不能承诺产品路线。 |

证据：[Metal LDR 格式][int8-metal-ldr]、[Metal 像素格式定义][int8-metal-formats]、[Apple GPU 功能表][metal-table]和 [AFM §6][optimization]。Khronos 的 `decode_unorm8` 选项只说明一条标准技术路线，**不能据此声称 Apple Metal 暴露同名开关或原始 UNORM8 直连能力**。

### 10.7 真正决定收益的，是有没有片上供数通路

如果解压出的 INT8 tile 能留在寄存器、共享存储或 Matrix Core 能访问的片上缓冲中，压缩可能持续减少 DRAM 权重流量。仍要测解码、数值转换、tile 重排和同步吞吐能否跟上；单通道纹理通常仍通过多分量接口返回，不能只按一个有效分量估算内部搬运。

如果每次使用前都先解压完整权重、写回 DRAM，再让 Matrix Core 读，可能更差。假设 N 个 INT8 权重、6×6 LDR、各阶段都到达 DRAM、无缓存复用，单次流量约为：

```text
原 INT8：                 N 字节读取
先解压写回再计算：        0.444N 读取 + N 写入 + N 再读取 = 2.444N
```

这不是实测，但说明“压缩率 2.25×”可以对应“反而搬更多数据”。若只在加载时解压一次再常驻，则主要节省模型文件空间，不再持续节省运行时权重占用。

即使片上通路成立，整个模型的收益仍取决于权重占总流量的比例。假设权重流量占 40%，权重字节减少 55.6%，总流量也只减少约 22.2%；整机延迟还受算力等瓶颈约束。

### 10.8 对我们的建议：可以原型验证，但不要先定为默认格式

建议先比较三类路线，而不是先假定 ASTC 必胜：

| 路线 | 精度合同 | 对 INT8 Matrix Core 的含义 |
| --- | --- | --- |
| INT8 的无损编码：零值掩码、位平面/熵编码等 | 严格还原原 INT8，不新增权重误差 | 解码输出 INT8；是否划算取决于真实分布和解码器 |
| 4 bit 索引/LUT，或低位整数打包后展开 | 有损还是无损取决于原权重是否本就在有限码表内 | 可查表恢复 INT8，或符号扩展成 INT8 运算；要匹配尺度，不要求原生 INT4 MAC |
| ASTC-LDR → INT8 | 通常有损，只有实际逐元素相同才可声称相对 INT8 无损 | 主要优势是复用已有纹理解码器；接入和重排成本必须实测 |

无损 INT8 压缩并非空想：NVDLA 公开了“零值掩码 + 非零权重 + 分组大小”的真实存储格式。[NVDLA 文档][int8-nvdla] 但这不意味着任何稠密 INT8 模型都会变小。按简化的一位掩码方案，零值比例 p 时约需 `1+8(1−p)` bit/weight，不计分组元数据也要 p>12.5% 才比原始 8 bit 小；不能把已有零值编码与重新剪枝导致的有损混淆。

推荐的验收顺序：

1. **先过供数门槛**：确认 ASTC 解码输出能到哪里、Matrix Core 从哪里取数，是否必须回写 DRAM，激活/权重零点和累加规则是什么。只有 INT8 支持信息还不足以作芯片级决策。
2. **再过整数重建门槛**：对真实权重比较 5×5、6×6；记录实际总字节、逐元素变化比例、最大整数偏差、零值变非零和饱和比例。选择与目标 GPU 一致的解码舍入模式；`astcenc -decode_unorm8` 不是通用硬件一致性保证。[Arm 解码精度说明][astc-encoding]
3. **再过质量门槛**：依次测浮点参考、现有 INT8、INT8+ASTC、恢复训练后版本，区分两次损失；阈值用产品既定预算，不凭格式名指定。敏感层可保留原始 INT8，不一定要求 Core 支持 FP16。
4. **最后过性能门槛**：相同模型任务和精度目标下，比较 ASTC、无损压缩、低位打包/LUT 和原 INT8 的端到端延迟、DRAM 字节、片上占用与能耗。计入转换、重排、同步和回退元数据。

**当前建议：有现成 ASTC 解码器、能片上供给 Matrix Core、允许恢复训练时，值得做 ASTC-LDR 原型；没有直达供数能力或必须逐位保真时，优先评估更简单的 INT8 无损编码/整数打包。能压缩是确定的格式可行性，质量能否接受和芯片上是否更快，则必须留给真实模型验证。** 本节没有进行 ASTC 编码误差或芯片性能实测，不把公式估算当测试结果。
